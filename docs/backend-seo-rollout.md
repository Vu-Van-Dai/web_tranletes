# Backend SEO rollout

Backend-first compatibility phase. No EF migration, UUID change, R2 object migration, package format change, or image worker configuration change. New API paths: /api/comics/by-slug/{houseSlug}/{comicSlug} and /api/chapters/by-slug/{houseSlug}/{comicSlug}/{number}. Existing ID endpoints and package URLs remain untouched. /sitemap.xml adds published non-mature chapters, visible genres and nonempty houses. /sitemap.xml?friendly=true is opt-in ONLY after Pages implements the new routes and redirects. URLs capped at 50,000; sitemap partitioning is future work.

Azure deployment: preserve locally modified deploy/backend.Dockerfile and deploy/docker-compose.yml, root .env and /data/postgres. Check branch and remote diff; back up database again immediately before deploying. Tag old image for rollback. Rebuild backend alone and use compose --env-file ../.env up -d --no-deps backend. Do not use compose down or prune R2/cache. Validate API and reader, compare package URL/version/size/checksum for the same published chapter before and after, and verify img.rongnho.shop response X-Cache (MISS from R2 then HIT in the same edge location, or ORIGIN fallback) and immutable Cache-Control. CI includes existing worker cache tests. Frontend friendly routing, activation, and ad provider enhancements are separate changes.
